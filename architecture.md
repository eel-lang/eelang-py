# eelang — архитектура пакета

Пакет `eelang` берёт `.eel`-исходник, парсит его PEG-грамматикой форка, десахарит в
стандартный Python AST и исполняет. Семантика фич не менялась; здесь — упаковка,
границы и решения.

## Компоненты

- **C-расширение парсера** (`eelang._parser`) — токенизатор + PEG-парсер (pegen из
  грамматики форка), собраны как C-расширение. Вход: `.eel`-источник; выход: AST.
  Опирается на internal-заголовки CPython → отдельный wheel под каждую платформу/версию 3.15.
- **Десахар** (`eelang.desugar`) — eelang-узлы → стандартные `Match`/`FunctionDef`/`Call`,
  затем `compile()` в байткод.
- **Runtime** (`eelang.MatchError`) — подкласс `ValueError`, импортируется явно
  (`from eelang import MatchError`). Десахар эмитит `raise eelang.MatchError(...)` с
  гарантированным `import eelang` в модуль (не зависит от пользовательского импорта).
- **Runner** (`eelang.__main__`, console-script `eelang`) — `eelang script.eel`: читает,
  парсит, десахарит, компилит, исполняет. Единственный способ запуска.

## Семантика фич (перенесено из форка без изменений)

- **assert-паттерны**: `assert P = e` десахарится в `match e: case P: pass` (иррефутабельный)
  либо `match (.0 := e): case P: ... case _: raise MatchError(.0)`. Провал → `MatchError`
  (аргумент — значение при одном `=`, кортеж субъектов при нескольких). Под `-O` не
  вырезаются. `assert x = 1, "msg"` → `SyntaxError` (неоднозначно).
- **match def**: `case if guard:` (guard-only) разрешён только здесь; провал без `else` →
  `MatchError`; докстринги есть, defaults/kwargs — нет.
- **Пайплайны**: `..f(x)` = `f(x, значение)`; блочная форма — блок первым аргументом;
  `..match:` недеструктивен (нет совпадения → значение не меняется, ошибки нет);
  `..assert:` → `MatchError`, переменные паттерна связываются в охватывающей области;
  `..` только с новой строки, перед цифрой не распознаётся (`.5` остаётся float).
  Присваивание не обязательно: «голый» многострочный пайплайн
  (`value NEWLINE ..steps`) вычисляется ради побочных эффектов, значение
  теряется (при statement-шагах протекает через `.0`).

## Решения и инварианты

- **Гейт** — только `.eel`; `.py` не перехватывается.
- **Минимальная версия** — CPython 3.15; платформа — x86_64 (manylinux2014).
- **Запуск** — только прямой (`eelang script.eel`).
- **MatchError** — только в пакете, не в builtins.
- `match` и `..match:` недеструктивны и идентичны питоновскому — менять запрещено.

## Изменения против форка

- Дистрибуция: PyPI-пакет вместо форка.
- Парсер: C-расширение из грамматики/токенизатора форка вместо правки интерпретатора.
- Гейт `.eel` (в форке его не было).
- `MatchError`: из builtins в пакет + явный импорт.

## Сборка

Из форка извлекаются грамматика, pegen-генератор и C-код парсера/токенизатора — они
переезжают в пакет. Полный checkout CPython удаляется из рабочего дерева; в истории git
он пока остаётся (восстановим при необходимости).
