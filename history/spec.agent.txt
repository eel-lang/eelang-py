я собираюсь сделать форк от ветки cpython 3.15

назвать этот форк eelang (Erlang-friendly Python)

расширение исходных файлов остаётся .py, sys.implementation.name остаётся "cpython"

В общем, синтаксис останется питоновским. но расширится за счёт замены = на паттерн матчинг

основные фичи

1) заменяем = на pattern matching

Point(x, y) = p

это валидный синтаксис. В левой части может быть все что позволяет оператор match..case, кроме условий if

Note: аналог из Ruby:

p => Point(x, y)

реализовывать => не нужно, это только аналогия для справки

2) match становится деструктивным

Если не сматчилось ничего, должен быть MatchError

Чтобы гарантировать отсутствие ошибки, нужно добавлять одним из вариантов case _:

Note: в Ruby оператор case уже деструктивный

3) MatchError

наследуется от ValueError. в args кладётся несовпавшее значение (аналог badmatch из Erlang)

Цель:

этот форк CPython делается с целью быть дружественным к проекту https://github.com/benoitc/erlang-python

и добавляет в питон принцип "let it crash"

включение фич

и новый синтаксис =, и деструктивный match включаются только через

from __future__ import pattern_matching

без него модуль ведёт себя как чистый CPython 3.15:
- новый синтаксис даёт SyntaxError
- match проваливается молча, как раньше

флаг можно также передать в compile(src, flags=__future__.pattern_matching.compiler_flag)

предлагаемая реализация

для тех случаев, которые в данный момент не приводят к SyntaxError, реализация = остается той же:
- = остаётся обычным присваиванием во всех случаях, где левая часть валидна в CPython 3.15 (вариант B)
- a.b = v и a[i] = v остаются записью
- a, *rest = seq остаётся распаковкой с ValueError
- x = expr (capture) остаётся обычным присваиванием и никогда не падает

pattern matching применяется только когда левая часть не является валидной целью присваивания:
Point(x, y) = p, 5 = x, (1, 2) = t, (1 | 2) = x, {"a": x} = d, p as q = v

решение "старое поведение vs pattern matching" принимается на этапе парсинга:
грамматика статична, patterns '=' rhs парсится всегда, существующие правила присваивания идут первыми (PEG ordered choice)

план правок в CPython 3.15

- Grammar/python.gram: альтернатива a=patterns '=' b=annotated_rhs в правило assignment + правка invalid_assignment; make regen-pegen
- Include/cpython/compile.h: CO_FUTURE_PATTERN_MATCHING = 0x2000000 + добавить в PyCF_MASK
- Lib/__future__.py: feature pattern_matching, _Feature((3, 15, 0, "final", 0), None, CO_FUTURE_PATTERN_MATCHING)
- Python/future.c: ветка в future_check_features
- Objects/exceptions.c + Python/bltinmodule.c: MatchError, подкласс ValueError
- Parser/Python.asdl: узел MatchAssign(pattern, value) + Python/ast.c, Python/ast_opt.c, Python/ast_unparse.c, Python/symtable.c
- Python/codegen.c: codegen_match_assign на базе codegen_pattern/fail_pop; fast-path capture -> обычный STORE_FAST; проверка флага; в codegen_match - raise MatchError(subject) при провале, если флаг включён
- тесты: Lib/test/test_match_assign.py, Lib/test/test_future.py; доки Doc/

файл без from __future__ import pattern_matching должен оставаться на 100% валидным CPython 3.15
