# eelang v3 — надмножество CPython 3.15

Согласованный дизайн (13.10.2026). Предыдущая итерация v2 — в
`eelang-match-case-extension` (deprecated), её ветка используется только как справочник.

## Принцип

Форк — **чистое надмножество** CPython 3.15: ни один валидный CPython-код не меняет
поведения; все новые формы вешаются на синтаксис, который в CPython — `SyntaxError`.
Поэтому **гейта нет**: ни `.eel`, ни future-флага. `match` остаётся мягким словом
и **недеструктивным** (как в питоне).

## Строгий запрет (важно)

`match` (обычный) и `..match:` **полностью совпадают с питоновским `match`**:
недеструктивны, та же семантика, те же `SyntaxError` на тех же местах.

**Запрещено менять `match` и `..match:` без явного утверждения** автором спеку —
и даже при таком утверждении решение согласуется **двумя** отдельными вопросами.
Любое расхождение с питоновским поведением — баг.

Валидный питоновский `match`/`case` не затрагивается; guard-only клоз `case if g:`
разрешён **только** в `match def` (в `match`, `..match:` и `assert` он невалиден).

## Фичи

### 1. assert-паттерны

```python
assert P1 = e1, P2 = e2 if guard
```

Биндинги и проверка формы. Провал → `MatchError` (args: значение при одном `=`,
кортеж субъектов при нескольких). Под `-O` паттерн-ассерты **не вырезаются**
(в отличие от обычного `assert`).

Запятая: наличие `=` делает утверждение паттерн-ассертом (формы с сообщением у него
нет). `assert x, "msg"` — обычный assert; `assert x = 1, "msg"` — `SyntaxError`
(неоднозначно, отбрасывается).

### 2. match def

Как в v2:

```python
match def f(x):
    case P = x if guard:
        ...
    case if guard:          # guard-only клоз (≡ case _ if guard:)
        ...
    else:
        ...
```

`case if guard:` — guard-only клоз, эквивалентен `case _ if guard:` (параметры уже
в скоупе). Разрешён **только** в `match def`; в `match`, `..match:` и `assert` —
`SyntaxError`.

Провал без `else` → `MatchError`. Докстринги поддерживаются, defaults/kwargs — нет.

### 3. Пайплайны и whitespace

- `=` допускает перенос строки с отступом:

  ```python
  square =
      lambda x: x*x
  ```

- `.`-продолжение — чистый синтаксический сахар (семантика обычного питона):

  ```python
  items =
      MyModel.objects
      .filter(active=True)
  ```

  `.` начинается с новой строки, отступ ровно как у выражения.

- Пайплайн `..` — значение передаётся **последним** аргументом:

  ```python
  val =
      [1, 2]
      ..map(square)      # == map(square, [1, 2])
  ```

- Блоковая форма — блок передаётся первым аргументом:

  ```python
  val =
      [0, 1, 2]
      ..filter: None       # == filter(None, [0, 1, 2])  → [1, 2]

  val =
      [0, 1, 2]
      ..map:
          lambda x: x*x
  ```

- `..match:` — match-выражение: **обычный питоновский `match`** (недеструктивный):

  ```python
  val =
      [1, 2, 3]
      ..match:
          case [a, b, c] if a < b:
              a + b + c
          case [a]:
              a
          case _:
              0
  ```

  Значение пайплайна = выражение выбранного case. Guard'ы (`if`) поддерживаются,
  body — одно выражение, в той же строке или блоком (как в обычном питоне).
  **Нет совпадения → значение не меняется, ошибки нет** (без `MatchError`).

- `..assert:` — паттерн-проверка (только блочная форма):

  ```python
  p =
      Point(1, 2)
      ..assert:
          Point(x, y)   # паттерн; объявляет x, y в охватывающей области
  ```

  Провал → `MatchError`. Значение проходит дальше; переменные паттерна (`x`, `y`)
  связываются в охватывающей области (как у assert-паттернов).

  `..` — только с новой строки, отступ ровно как у всего пайплайна; перед цифрой
  `..` не распознаётся (`.5` остаётся float-эдж-кейсом обычного питона).

## Реализация (эскиз)

- Всё десахарится в существующие AST-узлы (`Match`/`FunctionDef`/`Call`); новых
  runtime-механизмов и правок кодогена паттернов нет. `MatchError` — подкласс
  `ValueError` в builtins.
- Subject каждого assert-паттерна вычисляется один раз (temp-имя `.N` в десахаре,
  без коллизий — имена с ведущей точкой пользователь напечатать не может).
- assert-паттерны десахарятся в `match` (не в `assert`), поэтому под `-O` они
  **не вырезаются** без спец-случая в компиляторе.
- Пайплайны — правка **грамматики**, не токенизатора: блочная форма (`name =` +
  INDENT/DEDENT) и inline `a ..f(...)`/`a ..f: expr` (через два DOT-токена в
  `primary`). `..` — два `.`, поэтому `.5` и `...` не затрагиваются.
- Шаги `..match:`/`..assert:` десахарятся в последовательность statement'ов с
  синтетической `.N` (match/assert — statement'ы, их нельзя вложить в выражение);
  `.N` видна в `locals()` — тот же трейдофф, что у assert-паттернов.
- База — `cpython-3.15-latest/cpython-3.15` (снапшот `3.15.0+dev`, без .git):
  `git init`, базовый коммит, ветка `eel`.

## Открытые детали (мелкие)

- Правило «есть `=` → паттерн-ассерт» фиксируется тестами (включая
  `assert x = 1, "msg"` → SyntaxError).
