# Расширение match/case — принятый дизайн

Принят по итогам брейншторма над `history/spec.new.txt` (рабочие заметки —
`.thinkrail/context/TASK-match-case-extension.md`). **Реализация не начата**;
когда формы будут реализованы, этот документ вольётся в `eelang` (SPEC.md).

## Решения (закрыты пользователем)

- B-стейтмент `Point(x, y) = p` и текущий деструктивный `match expr:` **не меняются** —
  всё новое строго аддитивно.
- Все новые формы — только при `from __future__ import pattern_matching`;
  без флага — SyntaxError, поведение чистого CPython 3.15.
- `else:` — только в новой форме `match:`; в классической `match expr:` гарантия
  остаётся `case _:`.
- `MatchError.args` при провале case с несколькими `=`: кортеж всех субъектов;
  при одном `=` — само значение (как у B-стейтмента).
- `match def`: матчинг только именованными `=`-формами (паттерн `=` выражение,
  где выражение — обычно параметр); `self` матчится лишь если явно назван
  (напр. `X = self`); параметры — обычные позиционные (аннотации можно),
  без defaults/kw-only/*args/**kwargs.
- Расширение исходных файлов — `.py` (не `.eel`).

## Синтаксис

```python
# 1) match без аргумента
match:
    case Point(x, y) = p, mode = "special" if x > y:
        ...
    case ...:
        ...
    else:
        ...                     # гарантия от MatchError (только в этой форме)

# 2) короткая форма — стейтмент «связать или упасть»
match Point(x, y) = p, my_var = list() if x > y

# 3) диспетч
match def f(p: Point, mode: str):
    case Point(x, y) = p, "special" = mode if x > y:
        return "special"
    else:
        return "other"
```

## Семантика

- `case P1 = e1, …, Pn = en if g:` ≈ один clause матча на кортеже: субъект —
  кортеж `(e1, …, en)`, паттерн — `(P1, …, Pn)`, guard — `g`. При одном `=`
  кортеж не строится.
- Cases пробуются сверху вниз; субъекты case вычисляются только когда до него
  дошло дело (слева направо); первое совпадение (все `=` + guard) — его тело.
  Провал всех без `else` → `MatchError` (args по правилу выше).
- `else:` = хвостовой неохраняемый `case _:`.
- Короткая форма = `match (e1,…): case (P1,…) if g: pass` — связывает и уходит;
  провал → `MatchError`.
- `match def f(params):` = `def f(params): match: …` — тело функции целиком
  диспетч; имя доступно (рекурсия), `return` работает, self матчится только
  если явно назван.

## Реализация (эскиз)

- Все формы десахарятся в существующие узлы `Match`/`FunctionDef` — новых
  runtime-механизмов и изменений кодогена паттернов нет.
- Гейт флага: парсер не знает future-импортов (они читаются после парсинга),
  поэтому нужен один узел-маркер, проверяемый в symtable и десахаряемый
  до кодогена — деталь реализации.

## Отложено явно

- `else` в классическом `match expr:` — не делаем (старую форму не трогаем).
- Неявный кортеж аргументов в case (эрланг-клозы без `=`) — не делаем.
- defaults/kw-only/*args/**kwargs в `match def` — не делаем.
- Расширение `.eel` — не делаем.
